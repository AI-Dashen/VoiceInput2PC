# 万能输入法 v0.8｜产品方向冻结稿

日期：2026-10-13  
状态：IMPLEMENTING；效果与一级交互方向已确认，代码和本地构建已通过，真机完整验收 PENDING。

## 一句话目标

把 v0.7 的“手机文字送到 Windows 当前光标”升级为一个真正的中文输入系统：同一个 APK 同时提供 Android 系统输入法和长文本工作区，文字键盘、本地语音与多目标路由共用一套输入会话。

## 产品参考与边界

- **雾凇拼音（Rime Ice）**：学习离线中文方案、词库组织、全拼/双拼/T9 配置和长期维护方式；它不是可直接换皮的 Android 键盘。
- **豆包输入法**：只研究官方产品体验和合法取得 APK 的静态组件结构，关注语音状态、候选、设置与引导；不复制闭源代码、模型、资源或认证逻辑。
- **BiBi Keyboard**：研究 Apache-2.0 源码中的离线 SenseVoice、VAD、取消、预览与 IME 生命周期。
- **万能输入法自身**：拥有 UI、InputSession、目标路由、个人语言画像、Windows Relay 与最终产品行为。

## 三条输入路径

1. **本机当前输入框**：26 键/九宫格/本地语音，最终只写入当前有效 `InputConnection`。
2. **App 长文本工作区**：混合打字与语音，允许编辑、历史和导出。
3. **受信任终端**：在系统 IME 中用户明确切换输出目标后，稳定文字进入私有远端草稿；只有点击“发送”才沿用 v0.7 Relay 进入电脑当前光标。

系统 IME 不自动发送，也不把本机上屏文字同时转发。密码字段强制本机并禁用语音、学习、历史和 Relay。

## 核心状态机

`IDLE → COMPOSING/LISTENING → RECOGNIZING → PREVIEW → COMMITTED → IDLE`

- 每个输入会话绑定 `sessionId + target + package + fieldId + inputType + generation`。
- 拼音组合和语音临时结果只进入 composing/preview，不进入历史和 Relay。
- 只有候选确认或 ASR final 才成为稳定文本事件。
- 焦点、宿主、generation 变化时，旧回调作废，绝不能进入新输入框。
- 已提交撤销仅在光标前文本仍与提交内容一致时执行，否则提示无法安全撤销。
- Editor action 只允许用户显式点击触发；语音结束不等于发送。

## 首版范围

### P0

- 自有 InputMethodService 与启用引导。
- 26 键全拼、候选、选词、删除、空格、换行、中英文和符号。
- 本地录音、取消、final 预览与显式完成。
- 当前输入框与 App 工作区两个目标。
- v0.7 Windows Relay 不回归。

### P1

- 真正的九宫格拼音消歧。
- 连续分段语音与标点。
- 统一个人词条：用户确认后的词同时影响 Rime 用户词典和 ASR 后处理纠错。
- 多电脑目标切换与错误目标防护。

### 暂不进入 v0.8 首验

双拼、手写、云同步、皮肤商店、表情商店、云端 LLM 改写、唤醒词、后台常听、自动发送、模型训练、通用蓝牙中文 HID。

## 隐私模式

- **Local**：拼音、候选、语音和标点全部在本机；检测到所需模型不可用时明确失败，禁止静默切云。
- **Auto（未来）**：必须单独开关和说明数据去向；本版不默认实现。
- 同一 APK 的多进程共享 UID 与 manifest 权限，因此多进程只能提升稳定性，不能声称物理隔离网络权限。

## 进入开发的 Gate

1. 用户确认 Antigravity 效果图和关键流程。
2. Probe A：Android 16 IME 中主动点击麦克风，安全录音、取消并释放音频。
3. Probe B：SenseVoice 单实例冷/热启动与真实中文 final，Local 模式零网络。
4. Probe C：librime + Rime Ice 最小全拼候选进入 `setComposingText/commitText`，焦点切换零误提交。

三个 Probe 均通过后才扩展完整九宫格与个性化词库。
