# 0.8.33 本地 ASR 空闲内存分析（只分析，未改运行策略）

日期：2026-10-23

## 结论

当前客户端 `OfflineSpeechRecognizer` 在完成或取消后 60 秒执行的是 `unbindService`。这只断开 Binder；它没有向 `LocalAsrService` 发出“释放模型”命令。

独立进程 `:local_asr` 内的 `prepared` 模型只在以下情况释放：

1. 原生引擎错误后 `invalidateEngine()`；
2. `LocalAsrService.onDestroy()`。

正常识别结束只调用 `cancelStream()` 并清空 PCM，模型和 MNN runtime 继续驻留。因此此前观察到的约 1.18GB Swap 保留与源码行为一致，不能把客户端 60 秒解绑当作模型已经释放。

## 下一阶段安全设计

需要单独实现带 generation/lease 的空闲释放协议：

- 只有 `activeGeneration == 0`、`requestedGeneration == 0`、`pendingInteractiveGeneration == 0`、`batchGeneration == 0` 时才允许释放；
- 所有 live/file 请求建立 lease；完成、取消和异常路径都释放 lease；
- 空闲计时到期后在服务单线程 worker 中再次核对 generation 与 lease，再调用 `IndependentAsrNative.release()`；
- 新请求到达时取消旧的释放计划；释放与 prepare 串行，禁止与推理并发；
- 必须增加“释放瞬间新请求”“批量转写与实时识别竞争”“服务销毁”等竞态测试。

本批次优先修复九宫格交互，不修改已稳定的 ASR 引擎生命周期。状态：`PENDING`。
