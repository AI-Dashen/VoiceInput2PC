# 万能输入法 v0.8.37 低内存 ASR 验收报告

日期：2026-10-24  
状态：TESTED（本机独立运行与 APK 构建）；PENDING（用户真机交互验收）

## 结论

本轮已经定位并修复 ASR 热态约 1.2GB 的主要来源。问题不是录音缓存，也没有证据支持 Java 输入法主进程泄漏；主要原因是 MNN 3.6.1 以 `MNN_LOW_MEMORY=OFF` 构建时，将外部量化权重展开为较大的 CPU 运行布局，同时 Encoder 和 Logit 分别保留运行时内存池。

工程现在使用：

- MNN 3.6.1
- `MNN_LOW_MEMORY=ON`
- `MNN_SUPPORT_TRANSFORMER_FUSE=ON`
- Runtime `BackendConfig::Memory_Low`
- 现有 `Precision_High`、2线程与 `Power_High` 保持不变
- v0.8.36 的 60 秒热复用、75 秒服务端兜底和空闲进程退出策略保持不变

## 组件级实测

同一手机、同一模型权重、同一固定输入：

| 组件 | 原 PSS | 低内存 PSS | 变化 |
|---|---:|---:|---:|
| Encoder | 893,394 KB | 143,936 KB | -83.9% |
| Logit | 197,079 KB | 29,785 KB | -84.9% |
| 两者合计 | 1,090,473 KB | 173,721 KB | -84.1% |

低内存版完整 ASR 进程在 10 条语料回归中的峰值 RSS 为 223,020 KB；原版为 1,140,096 KB，降低 80.4%。

## 正确率与性能

使用 MNN 自带 10 条 AISHELL 中文 WAV：

- 10/10 两个版本均正常退出。
- 10/10 最终中文文本逐字一致。
- 原版总推理时间：33,567.39 ms。
- 低内存版总推理时间：20,422.69 ms。
- 推理时间降低 39.2%，约 1.64 倍加速。
- 公共基准音频两版均输出“广州市房地产中介协会分析。”

因此没有用 mock、替代模型或云端识别换取内存下降。

## 被拒绝的实验

1. 只设置 Runtime `Memory_Low`、但继续使用普通 MNN 库：Encoder 内存没有下降，峰值反而略高。
2. 设备中旧 low-memory 库关闭了 Transformer Fusion，现有 Encoder 无法运行，未用于产品。
3. 在 Session 完成初始化前调用 `releaseModel()` 会导致 Logit 运行错误，未进入产品代码。

## 实现

- `independent_asr_engine.cpp`：Encoder 与 Logit 使用 `Memory_Low`。
- 新增 `scripts/asr/build-mnn-asr-lowmem.sh`：可复现构建低内存且保留 Transformer Fusion 的 MNN。
- `build-independent-native.sh`：构建并打包专用低内存 MNN。
- 新增组件内存探针与 10 条语料对照脚本。
- 版本升级为 versionCode 47 / `0.8.37-low-memory`。
