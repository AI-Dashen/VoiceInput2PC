# 录音自动转写与说话人区分：0.8.26

## 当前结果
代码和安装包已完成；本地回归及手机Termux原生算法链路成功。**新版APK中从保存录音→系统后台调度→解码→分人→逐段识别→UI回听的完整真机验收仍为PENDING，不能写成已全部实机通过。**

## 用户操作
1. 管理页开始录音，可暂停/继续；点结束保存。
2. 成功保存的录音自动加入本地处理队列，使用系统JobScheduler，不需要联网。
3. 展开录音文件→文字与说话人；可看到解码、分人、转写或等待输入状态及完成段数。
4. 点击文字回听其时间段；可复制全文、重命名说话人、纠正片段归属，自动少分人时可新增说话人标签。
5. 失败/停止后点重试，保留原音频和已完成片段。不用重新录音。

## 实现
- Android MediaExtractor/MediaCodec流式解码M4A，降混/重采样为16kHz单声道PCM16，原子写入工作文件。
- sherpa-onnx 1.13.8 + pyannote segmentation3.0 int8 + 中英CAM++，仅对同一次录音内声音聚类，不建立跨录音身份库。
- 先分人/时间段，再送现有独立MNN ASR；长段最多20秒，避免拿整篇文字事后乱分给说话人。
- JNI模型调用完成即释放；转写复用已有:local_asr，不在新进程重复加载MNN。实时语音在片段边界优先，不能抢占正在执行的当前片段。
- :recording_worker以JobService运行，受BIND_JOB_SERVICE保护；无新增通用shell、Root、系统设置或云端API。
- 每录音独立execution锁保护完整任务；另一套短时文件锁＋AtomicFile保护JSON，UI改名不会被进度写入覆盖。
- 取消请求与真正停止区分CANCELLING/CANCELLED；完成前原子核对取消标记、完成数量和每段状态。
- 状态与已完成文字落盘；进程重启或系统暂停可继续；异常运行库加载、存储失败均显示真实失败，不写假完成。

## 实际证据
- 14项host自动化测试（含分段边界/取消完成门禁/任务锁互斥/停止等待/清理重入、麦克风互斥及既有输入回归）通过。
- 官方56.9秒四说话人录音：手机原生分人约5.927秒，137308KiB峰值RSS；自动0.75阈值得到4个标签、10段。
- 相同10段在既有MNN引擎实际转写全部得到非空文字，总20.278秒，1168180KiB峰值RSS。**未测参考逐字准确率，不承诺文字无错；上述时间不是完整APK总耗时。**
- 4项native错误输入拒绝测试通过。
- AAC测试文件已生成且probe正确；独立ART解码探针退出134，未产生解码成功证据，必须由安装后的APK验证，不将Termux测试冒充APK成功。
- Android存储/取消/JSON损坏/备份恢复/路径测试包构建，但未在真机执行。

## 已知边界
自动人数和归属会错；同一官方样本0.9阈值合并人、0.5阈值过度分人，因此0.75只是当前起点，不能当成普遍精度结论。声纹特征不是情绪识别，模型不会知道真实姓名。重叠标记来自实际输出的交叠和低置信启发式，不表示能把混在一起的声音完全分离。

本版单次转写上限60分钟。取消同步native分析时须等当前调用返回；不会强杀输入法进程。系统配额与休眠可能延后任务；未实现24小时常驻或重启后无需打开应用的守护器。物理侧键和AI直接读取记录均不在本轮。
